這個工具叫做 Claude Design 只要有訂閱 Claude code 就可以用，使用方法很簡單，直接在Claude code 輸入 /design 之後，它就會問你想設計什麼。 這部分就跟平常改程式碼一樣跟他討論需求，只是最後產出的是設計稿，而不是程式碼。 完成後會生成一個連結，打開就可以看到設計圖。 我很常使用的情境是，覺得畫面不太美觀但又想不到該怎麼做的時候，就會用Claude design 設計不同版本讓我選。

接下來直接用案例說明 (開設計圖) Claude design 連結打開後，其實就是網頁版 Claude 的其中一個頁籤 設計稿裡的介面就跟一般的設計軟體一樣，我可以直接在畫布上修改。 對畫布進行的改動，原來的 Claude code 對話視窗都可以偵測到。 但我還是會直接在 Claude code 的對話視窗請它自己修改，我怕自己操作會把設計圖弄亂。 (移到對比圖) 這個案例的問題是專案有一個地圖儀表板功能，上面會標示選中縣市開發案場的位置，原本的地圖只會顯示該縣市的範圍。 後來發現案場數量跟資料庫筆數不同，因為有些案場雖然歸這個縣市管理，實際位置可能在很遠的地方。 例如高速公路或是離岸風機，如果地圖只顯示單一縣市的範圍，這些案場會落在地圖外面，沒辦法正常呈現。 當時收到環工提出的需求後，我用 Claude design 先做示意圖，因為這個畫面的變動有點大，我不確定環工會不會接受。所以直接帶著示意圖去會議上討論。 環工看過之後，覺得這個方向OK，建議再增加拖拉和縮放的功能。 (關設計圖 ) 本來會議只是要討論該怎麼解決這個問題，直接變成當場就定案 如果一開始只有文字描述或口頭討論，大家對同一個需求可能會有不同的想像。

接下來分享第二個案例 專案當時遇到一個問題，新頁面的設計圖跟原有畫面風格不一致，但是專案又沒有一份完整的 UI 規範可以參考，所以實際做出來的畫面，有時候會跟環工想像的有落差。 因為專案裡已經累積不少元件，如果要全部人工盤點，再整理成文件，需要花不少時間。 所以後來我就請 AI 協助盤點專案裡的 UI 元件，整理成一份 UI 元件圖鑑。 這份圖鑑把專案裡元件和樣式整理出來，讓大家一目瞭然專案中各種元件的使用情形。 之後遇到設計圖跟既有畫面不一樣的情況，就可以直接拿這份圖鑑來討論。

07 / 9

(開圖鑑) 這份圖鑑其實就是一個 HTML 檔。 AI 盤點完專案之後，把專案中實際存在的樣式100%還原，照功能分類整理出來，有色彩、文字、頁面框架、區塊卡片...等等。 每個項目旁邊都會有標記 「標準」：專案裡最大量使用，或是已經做成共用元件。新的畫面就照這個做。 「待收斂」：同一件事目前有好幾種寫法並存。 「例外」：故意長得不一樣。 （捲到 6.2 圖示＋文字按鈕） 像 6.3 圖示＋文字按鈕 這邊就發現同樣是匯出按鈕，專案目前有兩種樣式，所以旁邊標示待收斂 以前這種差異，我只能用文字或截圖去描述，但現在有具體的畫面跟編號，討論的時候就可以直接說編號就好 而且下方都有標示目前這種樣式出現在什麼地方，要調整的時候也很方便 （回到簡報） 我跟環工討論畫面時，會優先用標準樣式。 待收斂的先標出來，等之後剛好改到相關功能再處理。這樣畫面不會一次變動太大。 之後遇到設計圖跟現有畫面不一樣，我會在 Issue 留言 設計圖跟專案規範不一樣，請問要使用圖鑑 6.3-A 標準樣式還是要照設計圖建立新樣式
